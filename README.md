# 민병희

Claude Code로 러닝 앱 **러닝그라운드**를 혼자 만들어 App Store·Google Play에 출시하고 운영합니다.
지금은 두 번째 앱 **모꼬지**(약속 지키기 앱)를 Claude Code로 만들고 있습니다.
무엇을 만들지와 판정 규칙은 제가 정하고, AI가 쓴 코드는 AI 검토자와 실제 폰으로 검증합니다.

관심사는 **왜 두 기기가 다른 답을 내는가**입니다. 실시간 동기화, 화면이 꺼지면 사라지는 기록, 기기마다 다른 측정값 같은 문제입니다.
그래서 하는 일의 큰 덩어리는 **노이즈 섞인 센서 신호(걸음 수·보폭·속도·위치)로 사람의 동작을 판정하는 규칙**을 정하고, 그 규칙이 실제로 맞는지 실기기에서 확인하는 것입니다.

**[모꼬지](https://github.com/Min-heee/mokkoji)** · 약속 지키기 앱 · 개발 중 (서버 연동 전)

주최자가 약속을 만들고 친구를 초대하면, 친구들이 명단에서 자기 이름을 골라 가상 포인트를 걸고 참여합니다.
주최자가 [시작하기]를 누르면 그때부터 서로의 위치가 보이고, 늦은 사람의 포인트는 제시간에 온 사람들이 나눠 갖습니다.
만난 뒤에는 기존 모임 정산(차수별 · 항목별 · 다중 통화) 화면으로 그대로 이어집니다.

- 1단계: 가짜 서버로 전 화면 동작 — main 병합 (2026-09-18)
- 2단계: 실제 지도, 앱을 켜 둔 동안의 GPS 도착 판정, 로컬 알림 — main 병합 (2026-09-19)
- 3단계: Supabase 서버 연동 — 클라이언트와 서버 규칙(로컬 PostgreSQL로 검증)까지 main 병합 (2026-09-19), 실제 서버 연결은 남음

`Expo` · `TypeScript` · `Supabase` — 지각 판정과 정산 규칙은 순수 함수로 떼어 테스트합니다. 커밋 전부 Claude Code와 함께 썼습니다.

**[품새 판정기](https://github.com/Min-heee/poomsae-judge)** · 브라우저 동작 판정 데모 · 공개

웹캠이나 녹화된 관절 좌표로 태권도 기본 동작(주춤서기 · 앞차기)을 공개된 규칙으로 채점합니다.
점수 옆에 측정값과 경계값을 같이 보여 줘서 왜 그 점수인지 읽히게 했고, 신뢰도가 낮거나 촬영 각도가 규칙과 다르면 점수를 매기지 않고 **판정 보류**로 떨어뜨립니다.
카메라 권한 없이도 전부 확인할 수 있게 합성 샘플 재생이 기본 모드입니다.

`Next.js` · `TypeScript` · `MediaPipe`(관절 33개) · `three.js` — 판정 규칙은 순수 함수로 분리해 테스트 281개로 고정했습니다. 기획서를 먼저 커밋하고 구현했습니다.

### AI와 일하는 방식

- **구현은 Claude Code와, 결정은 제가.** 러닝그라운드는 6월 이후 커밋의 88%, 모꼬지는 커밋 전부를 Claude Code와 함께 썼습니다.
  규칙과 우선순위를 왜 그렇게 정했는지는 커밋 메시지에 적어 둡니다.
- **AI로 AI를 검증합니다.** 큰 변경은 AI 검토자 여러 개를 동시에 돌려 반박하게 합니다. 관점은 "포인트가 두 번 쌓이지 않는가", "기록이 사라지지 않는가" 같은 것입니다.
  재현되거나 코드로 확인된 지적만 반영합니다. 화면을 끄면 기록이 사라지던 버그를 고칠 때는 검토자 30개가 결함 19건을 찾았고, 그중 2건은 가장 심각한 등급이었습니다.
- **테스트가 버그를 정말 막는지 확인합니다.** 고친 코드를 일부러 되돌려 테스트가 실제로 실패하는지 확인합니다.
  되돌려도 통과하는 테스트는 버그를 막지 못하므로 다시 씁니다.
- **마지막은 실기기입니다.** 두 폰을 나란히 들고 뛰고, 부정행위 판정은 직접 자전거를 타서 확인합니다.
  코드만 보면 맞는데 실제 폰에서는 달랐던 일을 사례연구에 적었습니다.
